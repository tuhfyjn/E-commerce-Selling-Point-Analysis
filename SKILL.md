# E-commerce Main Image Strategy

This skill treats product images as a **visual conversion system**, not as isolated posters.

## The original operating model

Use the **8-layer Visual Conversion OS**:

1. **Truth Layer** — lock what is factually true about the product.
2. **Friction Layer** — locate why shoppers do not click or buy.
3. **Reason Layer** — translate features into purchase reasons.
4. **Hook Layer** — choose the fastest reason to stop and care.
5. **Proof Layer** — make the reason visually self-evident.
6. **Journey Layer** — sequence the image set by decision order.
7. **Consistency Layer** — preserve product identity and visual system.
8. **Experiment Layer** — score, test, learn, and iterate.

The default consumer path is:

`recognize → care → believe → verify fit → feel safe → buy`

## Core equation

Use this as a heuristic:

`conversion image strength ≈ clarity × relevance × difference × proof × trust`

If any factor is weak, redesign the strategy before polishing the artwork.

---

# 1. Truth Layer — Product Truth Lock

Before writing copy, create a **Product Truth Lock**.

Record only supported facts:

- product name / category
- geometry and silhouette
- colors
- materials and finishes
- visible components
- logo / button / port / camera / interface locations
- dimensions and weight
- verified performance
- package contents
- compatible objects / devices
- warranty and service terms
- certifications and test evidence

Also record **forbidden mutations**:

- do not add missing components
- do not remove components
- do not move ports, buttons, cameras, logos, or structural details
- do not change proportions without evidence
- do not fabricate material, performance, certification, or accessories

If source images are incomplete, mark unknown areas as unknown.

Read [references/product-truth-lock.md](references/product-truth-lock.md).

# 2. Friction Layer — Decision Friction Map

Do not begin with “what selling points do we have?”

Begin with:

### Click friction
Why would the shopper scroll past?

### Purchase friction
Why would the shopper enter but not buy?

Map friction into four buckets:

- **Need friction** — “I do not feel this matters.”
- **Difference friction** — “They all look the same.”
- **Proof friction** — “I do not believe the claim.”
- **Risk friction** — “What if it does not fit / work / arrive safely?”

Prioritize one dominant friction at each stage.

Read [references/decision-friction-map.md](references/decision-friction-map.md).

---

# 3. Reason Layer — Purchase Reason Ladder

Translate every important feature through:

`fact → advantage → user outcome → purchase reason → evidence`

Example:

`aluminum frame → lighter body → easier to control → child can lift/manage it more independently → measured weight + scene proof`

Reject vague endpoints such as:

- premium
- upgraded
- powerful
- comfortable
- multifunctional
- high quality

unless they are converted into a concrete user outcome.

Rank candidate reasons using:

- user importance
- differentiation
- evidence strength
- visualizability
- comprehension speed

Use the strongest reason for image 1 unless trust/risk is more urgent.

Read [references/purchase-reason-ladder.md](references/purchase-reason-ladder.md).

---

# 4. Hook Layer — Hook-to-Proof Pair

A hook is incomplete until its proof is decided.

Choose one primary hook type:

- pain
- benefit
- contrast
- scenario
- emotion
- value bundle
- trust
- data

Then pair it with one proof mode:

- scene
- comparison
- measurement
- structural detail
- before/after
- scale
- social proof
- service/risk proof

The output is a **Hook-to-Proof Pair**:

`headline idea + visual action + evidence`

Example:

`“宝宝自己也能提” + child lifting the bike + verified product weight`

Read [references/hook-proof-pairs.md](references/hook-proof-pairs.md).

---

# 5. Proof Layer — No-Copy Proof Test

For every major image, run the **No-Copy Proof Test**:

> Hide every word. Can the picture still communicate the intended selling point?

- **Yes** → the image has visual proof.
- **Partly** → improve scene, comparison, scale, or structure.
- **No** → the image is only a poster; redesign it.

Prefer:

`visual proof > fair comparison > verified measurement > structural explanation > text-only claim`

The image does not need to explain every nuance without copy, but the core idea should survive.

Read [references/visual-proof-system.md](references/visual-proof-system.md).

# 6. Journey Layer — Five-Frame Conversion Path

Default sequence:

1. **Entry Frame** — earn the click.
2. **Reason Frame** — explain why this product.
3. **Proof Frame** — make quality/performance believable.
4. **Fit Frame** — remove size, usage, compatibility, or scenario uncertainty.
5. **Safety Frame** — reduce service, authenticity, shipping, or return risk.

This replaces the idea of “five posters” with **five decision jobs**.

Reorder by category risk:

- food / mother & baby: Entry → Safety/Trust → Reason → Proof → Safety/Service
- 3C/electronics: Entry → Reason/Performance → Fit/Compatibility → Proof → Safety
- high-ticket furniture/appliances: Entry → Reason → Scenario Outcome → Proof → Safety
- low-price fast-moving goods: Entry → Result → Proof/Comparison → Fit → Offer/Safety

Read [references/five-frame-conversion-path.md](references/five-frame-conversion-path.md).

# 7. Consistency Layer — Identity + Style + Rhythm

## A. Product Identity Guard

Across every generated image, preserve:

- silhouette
- proportion
- component locations
- brand marks
- material logic
- color logic
- package/accessory truth

## B. Reference Style Genome

When reference images are supplied, extract reusable style properties rather than copying the scene:

- lighting behavior
- contrast
- color temperature
- typography attitude
- information density
- composition tension
- product occupancy
- background complexity
- commercial mood

Use the **style genome**, not the reference’s exact scene.

## C. Gallery Rhythm Check

A five-image set should not be five versions of the same poster.

Aim for multiple visual jobs, such as:

- hero
- scene
- comparison
- close-up
- specification
- trust/service

As a default, use at least 4 distinct dominant visual structures across a 5-image set unless platform constraints justify repetition.

Read [references/consistency-and-style.md](references/consistency-and-style.md).

# 8. Experiment Layer — Score → Test → Learn

Use the 100-point rubric in [references/scoring-rubric-v1.1.md](references/scoring-rubric-v1.1.md).

If total < 85:

1. identify the two weakest dimensions
2. revise those first
3. rescore
4. stop when constraints or missing evidence prevent further improvement

Then design A/B tests with one major variable at a time:

- pain vs benefit hook
- scene proof vs product-only
- numeric proof vs non-numeric proof
- comparison vs single-product
- short headline vs explanatory headline

Primary image-1 metric is usually CTR. Downstream metrics may include CVR, add-to-cart rate, bounce rate, refund/return rate, and revenue per impression.

# Platform Constraint Router

Before finalizing image 1, determine whether the marketplace permits:

- text
- badges
- promotional language
- props
- models
- lifestyle scenes
- logos
- comparison elements

Do not assume the rule is current. If platform policy is material, verify the latest live policy.

Read [references/platform-constraint-router.md](references/platform-constraint-router.md).

# Output contract

At minimum output:

1. Product Truth Lock
2. Decision Friction Map
3. Top 3 Purchase Reasons
4. Primary Hook-to-Proof Pair
5. Five-Frame Conversion Path
6. Product Identity Guard
7. Reference Style Genome, if reference images exist
8. Evidence gaps
9. Compliance risks
10. Score
11. Two A/B tests

For machine-readable output, use [references/output-contract-v1.1.md](references/output-contract-v1.1.md).

# Quality gates

Before finalizing, verify:

- [ ] Product is identifiable within ~3 seconds.
- [ ] Image 1 has one dominant purchase reason.
- [ ] The headline uses shopper language.
- [ ] The key claim has a matching proof mode.
- [ ] The No-Copy Proof Test passes.
- [ ] Product geometry and components remain faithful.
- [ ] Reference style is distilled, not copied.
- [ ] The image set has visual rhythm, not five repeated layouts.
- [ ] Image 4 reduces mispurchase or fit uncertainty.
- [ ] Image 5 reduces risk instead of adding generic selling points.
- [ ] Every important number, certification, comparison, and guarantee has evidence.
- [ ] Platform-specific constraints are respected.
- [ ] Mobile-thumbnail readability is acceptable.
- [ ] A/B test variables are measurable.

---

# Final principle

**A main image is not decoration. It is a compressed purchase decision.**

The job is to make the shopper quickly understand:

`what it is → why it matters → why this one → why believe it → whether it fits → why it is safe to buy`
